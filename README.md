# Issue Watcher

בוט חינמי שרץ אוטומטית כל שעה, מחפש GitHub Issues חדשים שעונים על קריטריונים שאת/ה מגדיר/ה, מסנן אותם עם מודל שפה (Gemini) לפי פרופיל אישי, ושולח עליהם מייל מרוכז.

מתאים לכל מי שמחפש/ת Issues לתרום להם בקוד פתוח ולא רוצה לסרוק ידנית כל יום.

## איך זה עובד

1. כל שעה, GitHub Actions מריץ סקריפט פייתון.
2. הסקריפט מחפש ב-GitHub Issues חדשים מהשעה האחרונה, לפי שאילתה שאת/ה קובע/ת.
3. כל Issue חדש נשלח למודל Gemini עם תיאור הפרופיל שלך, שמחליט אם זה מתאים.
4. אם נמצאו התאמות — נשלח מייל אחד מרוכז עם קישורים והסבר קצר לכל אחת.
5. הבוט זוכר מה כבר נבדק (בקובץ `seen_issues.json`), כדי לא לשלוח כפילויות.

**עלות:** 0₪. כל השירותים המעורבים (GitHub Actions, Gemini API בדרגה החינמית, Gmail) חינמיים בהיקף השימוש הזה.

## התקנה

### שלב 1 — צרי ריפו חדש

צרי ריפו **פרטי** חדש בגיטהאב, והעלי אליו את הקבצים מהתיקייה הזו (שומרים על מבנה התיקיות `.github/workflows/` ו-`scripts/` בדיוק כפי שהוא).

### שלב 2 — מפתחות וסודות (Secrets)

ב-Settings → Secrets and variables → Actions בריפו, הוסיפי 5 Secrets:

| שם ה-Secret | מאיפה משיגים | הערות |
|---|---|---|
| `GH_TOKEN` | GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens | הרשאת **קריאה בלבד** (Public repositories מספיק לחיפוש בריפואים ציבוריים) |
| `GEMINI_API_KEY` | aistudio.google.com → API Keys | חינמי, לא דורש כרטיס אשראי |
| `EMAIL_FROM` | כתובת הג'ימייל שממנה יישלחו המיילים | |
| `EMAIL_TO` | כתובת המייל שאליה יגיעו ההתראות | אפשר זהה ל-`EMAIL_FROM` |
| `EMAIL_APP_PASSWORD` | Google Account → Security → App Passwords | דורש 2-Step Verification פעיל בחשבון. אם לא זמין בחשבון שלך (חשבון ארגוני/Workspace), שקלי חשבון Gmail אישי נפרד או שירות כמו Resend במקום |

### שלב 3 — הרשאת כתיבה ל-Actions

ב-Settings → Actions → General → Workflow permissions, סמני **"Read and write permissions"** ושמרי. (בלי זה, הבוט לא יוכל לשמור את היסטוריית ה-Issues שכבר נבדקו.)

### שלב 4 — הרצה ראשונה

בטאב Actions, לחצי על ה-workflow ולחצי **Run workflow** לבדיקה ידנית. משם הוא ירוץ אוטומטית כל שעה.

## התאמה אישית — מה לשנות ב-`scripts/check_issues.py`

### 1. איזה Issues לחפש — משתנה `BASE_QUERY`

```python
BASE_QUERY = "org:microsoft is:issue is:open no:assignee label:bug"
```

- **`org:microsoft`** — שם ארגון/משתמש. אפשר גם `repo:owner/name` לריפו ספציפי, או להשמיט לגמרי כדי לחפש בכל גיטהאב.
- **`label:bug`** — תווית לסינון. אפשר להוסיף עוד, למשל `label:"good first issue"`, או להסיר לגמרי.
- כל תחביר החיפוש הרשמי של GitHub (docs.github.com) עובד כאן.

### 2. כמה זמן אחורה לחפש — משתנה `LOOKBACK_HOURS`

```python
LOOKBACK_HOURS = 1.5
```

ברירת המחדל מחפשת Issues מ-1.5 השעות האחרונות (רשת ביטחון קטנה מעבר לשעה, למקרה של עיכוב בריצה). אם משנים את תדירות הריצה (השלב הבא), כדאי לעדכן גם את זה.

### 3. הפרופיל האישי שה-AI בודק מולו — משתנה `MY_PROFILE`

```python
MY_PROFILE = """
תארי כאן בעברית (או בכל שפה) מה מעניין אותך:
רמת ניסיון, שפות תכנות מועדפות, גודל משימה רצוי, מה לא מעניין אותך וכו'.
ככל שהתיאור מפורט וקונקרטי יותר - הסינון יהיה מדויק יותר.
"""
```

### 4. תדירות הריצה — קובץ `.github/workflows/watch-issues.yml`

```yaml
schedule:
  - cron: "0 * * * *"   # כל שעה בדיוק
```

תחביר cron רגיל. לדוגמה `*/30 * * * *` לכל חצי שעה, או `0 6-22 * * *` לפעם בשעה בין 6 בבוקר ל-10 בלילה בלבד (חוסך ריצות מיותרות בלילה).

### 5. כמות Issues מקסימלית לריצה — משתנה `MAX_PER_RUN`

```python
MAX_PER_RUN = 10
```

מגביל כמה Issues נבדקים ב-AI בריצה אחת, כדי לא לחרוג ממכסת החינם של Gemini. Issues עודפים יבדקו בריצה הבאה.

## פתרון בעיות נפוצות

- **"Write access to repository not granted"** — חסר שלב 3 למעלה (הרשאת כתיבה ל-Actions).
- **שגיאת IndentationError** — נגרמת בדרך כלל מעריכת קוד ישירות בדפדפן של גיטהאב. עדיף להוריד את הקובץ, לערוך במחשב, ולהעלות מחדש עם Upload files.
- **חריגת מכסה מ-Gemini** — הבוט מטפל בזה אוטומטית (ממתין ומנסה שוב, ובמקרה הצורך שולח מייל התראה) ולא קורס.
- **אין מייל אחרי ריצה מוצלחת** — כנראה שפשוט לא נמצאו Issues מתאימים בחלון הזמן הזה. אפשר להוסיף שורות `print` בקוד כדי לראות בלוג של הריצה כמה Issues נמצאו ומה הוחלט על כל אחד.
